# Architecture review after simplification

Reviewed `AGENTS.md`, the complete Assignment 2 PDF/rubric, MCP/research/configuration/state/LLM code, graph/supervisor, tests, dependency and environment examples, and existing architecture notes. No separate TA clarifications were present. No paid API calls were made.

## Changes justified in this step

- Replace the configuration-only retriever class with `search_web(query, settings=None)`. The Research Agent calls this function directly. Keep the request-scoped session lifecycle, schema validation, pagination and evidence checks. Use a callable logging filter instead of a custom Filter subclass. No pool, registry, additional provider or dependency is justified.
- Assemble `AgentResult` once for both success and failure; preserve required fields and append-reducer updates.
- Keep source snippets in structured `sources`, but only source IDs, titles and URLs in the report appendix. This removes duplicated evidence from downstream context without losing provenance. Consumers needing full evidence should use `sources`.
- Exclude live tests in default pytest configuration, regardless of an inherited RUN_LIVE_MCP flag. Keep explicit opt-in and limit the live test to one result. Confirm application `.env` loading with fake credentials and mocked retrieval.
- Preserve unrelated log diagnostics while suppressing sensitive Tavily tracebacks, including already formatted tracebacks and source lines. URL messages remain redacted. Arbitrary external tracing/wire logging still needs review before deployment.

A future approved live check should use the existing single-search test (one initialize, tool-list discovery and search, plus protocol cleanup; discovery may paginate), with no LLM generation. No live test was executed or requested during this review because it was unnecessary for these local changes.
